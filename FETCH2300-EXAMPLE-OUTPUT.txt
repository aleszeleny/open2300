CONFIGURATION SUMMARY DETAILS
════════════════════════════════════════════════════════════════════

The configuration summary shows:

Serial Device:
  - Exact path to serial device
  - Example: /dev/ttyS0, /dev/ttyUSB0, /dev/ttyAMA0 (Raspberry Pi)

Log Level:
  - 0 = No logging
  - 1 = Minimal (major operations)
  - 2 = Medium (includes data values)
  - 3 = Maximum (every operation)

Timezone:
  - Hours offset from UTC
  - Positive = East of UTC
  - Negative = West of UTC
  - Example: +1 (Central Europe), -5 (US Eastern), -8 (US Pacific)

Temperature Unit:
  - Celsius (°C) or Fahrenheit (°F)
  - Affects Ti, To, DP values

Wind Speed Unit:
  - m/s (meters per second)
  - km/h (kilometers per hour)
  - MPH (miles per hour)
  - Affects WS value

Rain Unit:
  - mm (millimeters)
  - inches
  - Affects rain measurements

Pressure Unit:
  - hPa (hectopascals) = mb (millibars)
  - inHg (inches of mercury)
  - Affects RP value


════════════════════════════════════════════════════════════════════
TIPS
════════════════════════════════════════════════════════════════════

1. Use LOG_LEVEL 1 for normal operation
   - See what's happening without too much detail
   - Verify configuration is correct

2. Use LOG_LEVEL 2 when troubleshooting data issues
   - See actual values as they're read
   - Verify units are correct

3. Use LOG_LEVEL 3 when debugging communication problems
   - See every operation
   - Identify where failures occur

4. Use LOG_LEVEL 0 in automated scripts
   - No log overhead
   - Clean data output
   - Or redirect: fetch2300 2>/dev/null

5. Always check the configuration summary
   - Ensures you're using the right serial device
   - Verifies units are what you expect
   - Shows timezone setting

6. Separate logs from data
   - fetch2300 > data.txt    (logs to screen, data to file)
   - fetch2300 2> logs.txt   (data to screen, logs to file)
   - Both can be useful for monitoring and archiving
